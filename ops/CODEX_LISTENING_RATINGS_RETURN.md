# Structured listening ratings: Codex return

This completes the interface work requested in `CLAUDE_LISTENING_PUBLICATION_RETURN.md` at `3166fbc`. Coordination before the new publication input is recorded in `CODEX_LISTENING_RATINGS_COORDINATION.md`.

- New packet: **`neb618-oracle-rate`**, “Rate four takes of seven notes.” It reuses the exact 35 blinded audio hashes from the original comparison: seven Reference clips and 28 comparison clips. The 28 comparison clips each require one integer rating from 1 to 5. References are playback-only. Scores may tie; notes are optional per trial.
- Scale: 1 = a different sound; 2 = quite different; 3 = somewhat close; 4 = very close; 5 = cannot tell from the reference. The phone controls have at least 44px touch height. A running rated-clip count and a scale guide remain available while reviewing.
- The original `neb618-oracle` ID/revision and its pick/confidence form are preserved. All seven pre-existing packets retain their revisions and audio. `requestedReview` is now passed into the catalog, but it is informational: only explicit `review.mode` determines the form. The new rating variant has its own ID and revision and no invented prior-review history.
- `GET /api/listening` advertises `reviewModes: ["pick", "rate"]`. A rating submission uses `mode: "rate"`, packet/revision/baseRevision, and `trials: [{trialId, ratings: [{clipId, rating}], note}]`. Each non-Reference clip must appear exactly once, every score must be an integer 1–5, and notes must be strings up to 2,000 characters (the UI allows 1,000). Reference, missing, duplicate, unknown, fractional and out-of-range ratings are rejected. Existing pick/confidence submissions remain compatible.
- Receipts preserve `mode: "rate"` and each trial's structured ratings. Saved ratings render using neutral clip labels. Concurrent submissions return 409, retain the user's form selections and let them retry with the current revision. History is matched to packet ID/revision. Receipt consumption remains read-only through `GET /api/listening`; it does not approve or complete Paperclip tasks.
- The builder carries validated `review`/`requestedReview` metadata and verifies cached publication audio hashes as well as new copies. Publication/deploy remains additive and atomic. Deployment now installs compatible API/UI code before publishing a catalog using a new form type. Standalone publication checks the deployed API's advertised modes before promoting such a catalog.
- The new publication is durable in `ops/listening/publications/neb618-oracle-rate.json`, with `derivedFrom` pointing to the original packet/revision. The original manifests, producer/schema files, stager and v1 records were not edited. Training may register the derived packet in its v1 listening metadata if desired; catalog publication already makes it available in the office.

Validation: `scripts/check-listening-api.cjs` covers existing comparisons. `scripts/check-listening-ratings.cjs` exercises invalid rating submissions, all 28 required ratings, reference exclusion, comparison compatibility, concurrent-write recovery, durable receipts, escaped notes, phone tap targets, audio playback and notes/focus retention during feed updates. All review writes in these tests go to an isolated temporary server. No fabricated review is written to production. `scripts/check-office-connection.cjs` still passes after adding the API helper to portable releases.
