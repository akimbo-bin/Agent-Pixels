# Paperclip live contract audit

Audited 2026-11-09 from repository source. Scope: exporter, Paperclip adapter, live normalization, polling contract and visual handoff journal. No Paperclip API calls, service changes or credential reads were performed. No applicable `AGENTS.md` was found in the repository or its parent directories.

### Polling and freshness

- Exporter timer: every 60 seconds, 5-second scheduling accuracy; each API subprocess can take 30 seconds. Requests run sequentially, and `exportedAt` is stamped before collection starts. The snapshot is therefore not a transactionally consistent view or an export-completion timestamp. [Timer](agentpixels-status/install.sh#L24), [timeout](agentpixels-status/export.py#L23), [timestamp](agentpixels-status/export.py#L46).
- Adapter: organization is considered fresh for 180 seconds by default; job/machine tasks advertise 600 seconds. Registry caches for 5 seconds; world server caches for 4 seconds and coalesces concurrent reads. Illustrated characters fetch every 5 seconds while visible with a 5-second request timeout. The effective update rate remains limited by exporter collection. [Adapter freshness](../scripts/live/adapters/paperclip-org.mjs#L21), [registry cache](../scripts/live/registry.mjs#L89), [server cache](../scripts/nebula-world-server.mjs#L14), [browser polling](../dev/engine/illustrated-characters.js#L47), [poll interval](../dev/engine/illustrated-characters.js#L57).
- Consumers apply different freshness limits: visual journal and illustrated roster use 90 seconds, while adapter uses 180 seconds. Journal additionally rejects timestamps more than 30 seconds in the future; adapter only checks maximum age, so future timestamps pass. [Journal gate](../scripts/handoff-journal.mjs#L8), [roster gate](../dev/engine/illustrated-characters.js#L14).

## Findings that affect organization integration

1. **A newly written error snapshot can report a running source.** A company/agents/issues/live-runs failure enters the outer catch, records only an exception class and still writes a fresh timestamp. The adapter derives `state` only from age, attaching errors as `why`; normalization preserves `why` only for `unknown`. Consumers of the task alone can therefore see `running` even with missing roster/workboard. The organization payload does retain `errors`. Make success/partial/failure explicit and preserve diagnostics independently of state. [Exporter catch](agentpixels-status/export.py#L107), [adapter result](../scripts/live/adapters/paperclip-org.mjs#L40), [normalizer](../scripts/live/registry.mjs#L45).

2. **Completeness is uneven.** Workboard fetches pages of 100 up to 5,000 and sets `complete` only after a short page; exactly 5,000 records conservatively remains incomplete. Offset pagination can still skip/duplicate records during concurrent changes. Live runs stop at 100 without a completeness/total marker; attention exposes incompleteness but does not fetch subsequent cursors; activity deliberately stops at 30. An empty/malformed object response may also be interpreted as an empty list by `items()`. Publish per-section completeness/limits and validate response shapes. [Pagination](agentpixels-status/export.py#L55), [list extraction](agentpixels-status/export.py#L29), [limited sections](agentpixels-status/export.py#L68).

3. **Company identity is not configurable end to end.** Exporter selects the first company whose name starts with `nebula`; journal and roster require exact `Nebula`; source lookup is fixed to `org.paperclip`; attention paths are fixed to `/NEB/`. Exporter includes `company.id` and `issuePrefix` but does not use a configured company ID or prefix for selection/links. Another company, renamed company, or multiple matching companies requires code edits. Prefer explicit company ID, source ID, base URL and issue prefix configuration. [Selection](agentpixels-status/export.py#L48), [attention paths](agentpixels-status/export.py#L82), [journal identity](../scripts/handoff-journal.mjs#L8), [roster identity](../dev/engine/illustrated-characters.js#L47), [connection configs](ct125-world-live.config.json), [SSH config](world-live.config.json).

4. **Current assignment does not identify the running issue reliably.** All assigned issues are available by stable IDs, but `agent.issue` is overwritten for every `in_progress` issue in ascending issue-ID order. Its `running` flag means that the agent has any running run, not that a run matches that issue. Use the already exported `liveRuns.issueId` to select the active issue or expose several active assignments. Job tasks use ticket alone as their key, so duplicate tickets across machines overwrite; VM116 render summary picks its first job. [Assignment](agentpixels-status/export.py#L70), [job IDs and render selection](../scripts/live/adapters/paperclip-org.mjs#L24).

5. **The documented allow-list has exceptions.** Inbox badges are copied wholesale; dashboard `agents`, `tasks` and `pendingApprovals` are copied as nested values without validation. Agent/issue names and descriptions are explicitly exported content, not secret-redacted content. Before supporting arbitrary organizations, validate a versioned schema and allow-list nested response fields as well. No actual secret disclosure was established by this source-only audit. [Inbox/dashboard](agentpixels-status/export.py#L89), [exporter claim](agentpixels-status/export.py#L7).

6. **Failure handling favors a small partial snapshot over last-known-good data.** Optional attention/activity sections catch failures separately; core Paperclip failure can discard roster despite earlier success. Missing or invalid usage JSON silently becomes empty jobs/machines; structurally valid but unexpected usage shapes can throw outside the Paperclip catch and prevent replacement, leaving the prior file. Transport/JSON failures normalize to `unknown`; the registry itself does not expire states from timestamps. Add section health, last-success timestamps, bounded retry and shape checks; make stale retained data distinguishable from a genuine empty result. [Optional catches](agentpixels-status/export.py#L90), [usage handling](agentpixels-status/export.py#L109), [registry failures](../scripts/live/registry.mjs#L84).

7. **Machine placement is incorrectly promoted to audio workload classification.** `renders.vm116` aliases the first job on VM116 solely because its `machine` equals `vm116`; there is no renderer/audio kind, output evidence, agent or issue-role filter. A Data job therefore becomes a task titled “VM116 renders.” The screen consumer uses that task for both the audio screen and Music Studio's working signal. Matching `workloadKey` prevents double-counting the alias and ticket task in the workload list, but the alias sorts first and wins equal freshness ranks, retaining the misleading render label. Bind room signals by explicit workload kind/room ID or a dedicated audio adapter; use machine health only for machine health. [Alias](../scripts/live/adapters/paperclip-org.mjs#L32), [Music signal](../dev/engine/illustrated-screen-programs.js#L8), [deduplication preference](../dev/engine/illustrated-screen-programs.js#L15), [audio screen](../dev/engine/illustrated-screen-programs.js#L31).

8. **A recently checked registration is not recent execution evidence.** Exporter copies job `state` and `checked` from `jobs-status.json`; it does not cross-check the queue driver, process, heartbeat or matching Paperclip run. Adapter turns `checked` into `updatedAt` and grants it a ten-minute freshness window. Rewriting the outer snapshot never refreshes `checked`, but a checker can refresh `checked` while preserving an outdated `running` registration. Prefer timestamps for observation, last execution evidence and state transition separately, with an explicit source-of-truth policy. [Copied fields](agentpixels-status/export.py#L109), [job freshness](../scripts/live/adapters/paperclip-org.mjs#L24).

During this audit, the coordinating agent reported the official `/live` response showing direct training telemetry at roughly 948 seconds old, `waiting`, “Queue complete · driver stopped unfinished jobs,” progress 93/95, while `paperclip.job.NEB-318` remained `running` with a roughly 143-second-old check and ten-minute freshness. It also reported `paperclip.renders.vm116` aliasing the Data job NEB-657 with the same `vm116/NEB-657` workload key. These are point-in-time observations supplied by the coordinating agent, not independently fetched by this audit. The code explains why these conflicting views can coexist: source ranking favors fresh known state, does not reconcile execution evidence, and machine-based aliasing determines the Music signal. Treat the registration as conflicting evidence rather than proof the stopped driver is running.

## Handoff guarantees and limits

The journal observes snapshots and writes only its own local visual journal. It requires a complete workboard, fresh valid timestamp and a newer source timestamp; the first accepted observation is a baseline. Subsequent recent `done` transitions route to a distinct parent-task owner and the source agent's manager (falling back to Lead/CEO), deduplicating recipients. Events are hashed from issue ID, completion token and recipient ID; only 200 events remain. It neither changes Paperclip nor represents a real dependency, acknowledgment or delivery. [Journal implementation](../scripts/handoff-journal.mjs#L8).

Because it advances only when `/live` or `/api/handoffs` requests invoke collection, this is a sampled visual history. Completions older than 30 minutes at observation, transitions occurring between snapshots, initial baseline work and invalid/incomplete periods may be omitted. A long unattended period does not produce a durable organization event log. Journal write failures surface a generic error; `/api/handoffs` returns 503 for that error. [Observation window](../scripts/handoff-journal.mjs#L13), [retention/save](../scripts/handoff-journal.mjs#L27), [server invocation](../scripts/nebula-world-server.mjs#L14).

## Smallest useful contract improvement

Keep the read-only snapshot boundary. Add `schemaVersion`, configured company identity, collection start/end, per-section `{status, complete, updatedAt, lastSuccessAt, error}` and explicit pagination metadata. Use stable IDs for all joins, run-to-issue matching and machine/ticket job identity. Derive source health from required sections, and share a freshness/clock-skew policy across adapter, journal and consumers. These changes would make another organization connect through configuration instead of edits scattered through the exporter and consumers.

Validation: existing `check-handoff-journal.cjs` and `check-handoff-routing.cjs` passed locally, covering baseline, stale/incomplete rejection, deduplication, persistence, reopened completions and manager/parent routing. A local normalizer probe confirmed that a `running` task's `why` is dropped. These checks do not verify the deployed exporter, SSH forced-command restrictions, current API responses or current snapshot contents.
